# 三视图联合摘要＋单Task Forward：seed0八任务结果与机制分析

分析日期：2026-10-20（Asia/Shanghai）。运行提交：`f057e7125787cf83dad1c7a34b31ff067d3a9a30`。
正式批次：`formal_seed0_20261020_01`；源实验分支：`codex/joint-view-summary-20261020`。

## 结论先行

单Task Forward在工程上可实现，固定联合摘要约节省30%的训练峰值分配显存，但本次实现没有带来精度收益。
在监督相同的对照中，提前合并摘要使最终test下降1.0614点；再增加普通融合器或MoE，又分别下降2.5402和2.5633点。
MoE确实按图片内容产生了不同路由，但没有优于普通融合器。当前证据最支持的问题是：**过早合并三视图证据，以及在冻结任务注意力之前自由改写摘要，未形成可泛化的联合表示。**
前半句是结构对照及性能事实；“信息损失／输入语义不匹配／过拟合”的具体分工仍属机制解释，未完成因果归因。

## 1. 本轮究竟改了什么、为什么需要这些对照

原三视图方法让同一套任务Selectors／Prompts分别处理Full、Person和Face，保留三份不同的任务CLS状态，最后融合。
新方法每层用同一组Selectors读取三路冻结图像流，但先将三组摘要合成一组，交给一个任务CLS及一条任务注意力／FFN路径。
三视图使用同一套冻结CLIP权重，不是三个参数独立的backbone。骨干不写回Adapter，分类头位置保持原位置。

```text
原方法：三组摘要 → 三路任务表示各自演化 → 三份任务CLS → 末端融合
新方法：三组摘要 → 一组联合摘要 → 一条Task Forward → 一份任务CLS
可学习版本的联合摘要 = 固定联合摘要 + 0.1 × 联合输入融合残差
```

四个新组均seed0、8任务×30epoch、batch64、主学习率0.0125、融合学习率0.0004、Adam每任务重置、cosine、auxiliary BCE=0。
原B0为已有seed0参照，保留auxiliary BCE=0.1。取消辅助监督的B0排除损失改动影响；固定联合摘要检验整个前移融合结构；
普通融合器检验可学习改写；MoE检验稀疏专家相对普通融合器是否值得增加。

普通融合器为2307→32→768；MoE每任务每层4名2307→16→768专家，soft Top-2，无噪声及额外负载损失。
12层均融合，Router读三路联合摘要及有效性；共有8×12=96套联合Router，每套4名专家，不再是三个视图各自一套Router。所有融合参数按任务独立，后续任务不再更新旧任务融合器、Router或Expert。
本轮不使用跨任务专家复用、频次冻结、DDAS、ParaX或独立Image-token Adapter。详细配置见同目录`joint_view_summary_experiment_20261020.md`。

```text

  → 固定联合摘要 30.9878（再−1.0614）
  → 联合融合MoE 28.4245（再−2.5633）
```

因此，MoE较原B0下降不能主要解释为“取消了辅助监督”。可学习残差在同监督、同单路径的对照中仍明显有害。

## 6. 从机制根源理解结果

### 6.1 冻结机制保护了旧任务，但没有保证新表示学得好

当前每任务整套融合参数被冻结，后续任务无法继续改写旧Expert和Router；旧参数核验已通过。
全人群test的平均forgetting分别只有：原B0 0.0071、取消辅助监督0.0064、固定联合摘要0.0072、普通融合器0.0107、MoE 0.0128。
固定／普通融合／MoE中，同一新类组从其引入阶段到最终阶段的组平均AP最大绝对变化分别约0.0155、0.0466、0.0465点。
这些变化远小于相对固定组2.5点以上的差距。冻结主要稳定地保存了各任务已经学到的表示；当前失败首先发生在表示学习与泛化阶段。
不能再默认解释成“旧任务仍访问的共享专家被新任务改坏”。

### 6.2 同一组Selectors意味着共同查询，不意味着三路摘要已经语义对齐

MULTI-LANE的Patch Selectors用任务查询读取图像证据，再将摘要交给任务MSA；Drop & Replace保留CLS并恢复Selectors。
这是对论文Summarize与任务路径机制的简述。[MULTI-LANE §3.3](https://arxiv.org/html/2405.15633v1#S3.SS3)

Full、Person、Face经过不同裁剪；同一查询可能分别读到场景、身体动作、局部表情。它们都与任务有关，却不必是可直接平均的同一信息。
本实现从三组各10份摘要，提前压成10份；一个任务CLS随后只能基于这一组合状态演化。旧方法则允许三份CLS分别积累证据，再在末端组合。
因此，一个合理解释是：在任务注意力判断信息价值之前，固定混合已稀释或抵消某些弱线索。现有结果没有直接测量“具体哪一种线索丢失”，此项仍需归因对照。

另外，固定前移组还改变了任务路径数和最终归一化位置：旧B0先归一化三路CLS再加权，新单路径归一化联合CLS。
故fixed对照检验整个结构，不能单独证明“单Task Forward必然不行”或“所有性能下降都来自摘要平均”。
每层都重新读取冻结证据，所以Face权重不是简单的0.2的12次方，不能用这种乘法解释损失。

### 6.3 本次“可学习融合”实质上是自由改写摘要，尚未约束它如何保留可靠证据

代码中的固定基底仍使用(.64,.16,.20)，Face不可靠时(.8,.2,0)。新增MLP或Expert读三路拼接输入，输出一个768维残差；
Router选择的是哪名融合Expert，并没有直接给三种视图学习一组非负、和为1的保留权重。
因此，“能同时观察三路”尚不等于“已经学会可靠地保留／补充／抑制三路证据”。

代码还把这个自由残差放在任务MSA的QKV投影之前，联合摘要之后没有再做一次LayerNorm；其改写会直接影响冻结注意力的key/value及CLS读取结果。
这与原MoE-Adapters在attention之后对token做专家适配、通过task-specific Router加权输出的接口不同。
[MoE-Adapters §3.3](https://arxiv.org/html/2403.11549v2#S3.SS3)

所以较有依据的假设是：当前可学习模块改变了预训练注意力依赖的摘要语义／几何，增加了任务训练集上的拟合空间，却没有形成可泛化的三视图组合方式。
这是假设而非已证实的唯一原因；尚缺关闭残差后的条件贡献、摘要方向／注意力变化和独立训练的token保留对照。

### 6.4 不是“专家几乎没参与”，也没有观察到全局固定路由

| 方法 | Validation：缩放后残差／固定摘要范数比中位数 | 96位置中最大平均范数比 |
|---|---:|---:|
| 普通融合器 | 0.1184 | 0.4211 |
| 联合融合MoE | 0.0840 | 0.3252 |


范数比已经包含0.1系数，是每个任务×层位置的平均残差范数除以平均固定摘要范数；表中最大值是96个位置的最大平均比，并非所有图片的上界。
它们不接近零，也没有NaN证据；不能沿用旧版“分支几乎无输出”的诊断。

固定task7 checkpoint上，validation的96个任务层中87个调用过4名专家、9个调用过3名；没有只调用同一对专家的全局静态池。
Top-2门控熵中位数0.6025（最大可能值log2约0.6931），也不支持把全局问题概括为全都硬饱和。
有2个位置的两名主导专家至少共同覆盖98%图片，局部集中仍存在；活跃次数不等于贡献或专业化。

进一步用保存的权重一阶／二阶矩扣除Face可靠性这个二值开关：96/96任务层仍有组内门控变化。
在可靠Face人群中95/96位置、在不可靠Face人群中96/96位置，都给超过两名专家分配过正权重；每张图只选两名，
因此同一可靠性组内必然有图片选择不同Top-2集合。两个split结论一致。这是实际内容路由的证据，**不是路由带来精度收益的证据**。
尚没有测专家输出之间是否形成互补语义分工。

### 6.5 “更会拟合训练集”与“更会融合视图”目前分开了

同为aux=0，普通融合器和MoE在8/8任务的末epoch训练BCE都低于固定组；但它们在两个split的8/8阶段mAP都更低。
例如task0固定组训练BCE约0.5868，普通融合约0.5668，MoE约0.5652，对应test却从35.0597降到30.6076／31.4339。
这个模式符合泛化恶化，而非仅仅“没有训练起来”；但单凭训练BCE不能完全区分容量过大与不合适的输入改写方式。

test最终普通融合器有21/26类、MoE有23/26类低于固定组；下降也包括Happiness等类别，不只是个别稀有类波动。
原始logit排序与保存概率排序的最终mAP差，五组两个split中最大约0.0035点，远小于当前性能下降。
因此，单纯更换分类阈值或统一温度不足以解释和修复这种排序损失。
