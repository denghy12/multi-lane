# 恢复历史评估标准与Full复现配置审计

2026-10-23。按用户要求，后续主报告恢复原samples_intersect_seen_classes标准；固定全人群保留为敏感性分析，不能混用阶段平均。

## 发现的两类原因

1. 评估标准发生变化：历史每个阶段只纳入在累计已见类别中至少有一个正标签的人物，随后对累计已见类计算mAP，最后对8阶段取算术平均。本轮固定所有人物，增加早期负例，因此AP及阶段平均下降。AP公式、类别顺序、任务顺序没有变化。历史32.5365/39.1445/32.5756/49.3827分别为test最终mAP/阶段平均mAP/cF1/oF1，不含validation列。
2. 旧代码Full重跑配置没有完全恢复：历史paired_full_person=true、margin.15、jitter.1/.2；前次R漏了这些参数，变为false/0/0。其训练轨迹从第一个epoch已与历史记录不同。最终阶段两边均5368人、26类，最终mAP相差.583不能用评估人群解释。遗漏参数的单独贡献尚未隔离，不能把所有分差都断言成某一个值造成。

## 恢复后的旧标准

- 每阶段mask = 在当前已见类的targets中至少一个等于1；不按预测、阈值、模型置信度或最终全部26类选择人群。
- Validation人数：2285/2375/2381/2397/2397/2397/2397/2397。
- Test人数：3142/4600/4691/5232/5342/5354/5367/5368。
- 当前8模型×8 test阶段筛出的IDs、targets及class indices，与历史存档逐值相同，共64项人群对照通过。
- 使用已保存的逐人预测只读复算，不改变权重；旧人群筛选后，早期batch组成与重新GPU评估不同，浮点排序可能有细小差别。因此前次R原生旧人群平均38.5130与缓存筛选38.5073相差.0057，不能混称逐值重放。最终阶段相同人群，结果完全不变。

## 后续更正：运行环境是已验证的复现因素

补齐paired配置后，CPU1包装运行仍沿前次偏离轨迹；原生旧入口在默认72线程下前两轮与历史loss精确匹配。额外受控原生CPU1短跑也回到偏离轨迹，排除了仅由包装器引起的解释。CPU正交初始化检查显示Prompt存在约1e−8差异且部分FP16舍入不同，随机数状态仍相同。这解释了为何仅比较seed/超参数不够。最终8任务是否重现全部四指标，仍等运行结束确认。
