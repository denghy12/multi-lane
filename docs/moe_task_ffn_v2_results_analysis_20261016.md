# Task-Forward MoE v2：三组 validation 结果与下一步

## 1. 结论

v2 成功解决了首版 Router 按任务/视图固定选专家的问题，但没有证明
动态 MoE 带来稳定性能收益。动态组最终固定全人群 validation mAP 为
42.2877，相对同协议 B0 的42.1912仅高0.0965；8阶段平均48.2518，
反低B0 0.1864。最终按原图分组 bootstrap 的95%区间为
[-0.748,+1.007]，跨0。动态组相对固定共享/固定视图最终分别高
0.5206/0.3120，区间也都跨0。

最关键的机制结果是：动态 Router 确实随图片切换专家，但专门专家的
实际输出远小于必经共享专家。task7 中，共享输出相对输入 token 的平均
范数比约3.509，专门输出只有0.263–0.304；共享分量约为专门分量的
11.6–13.4倍。关闭同一 checkpoint 的 MoE 残差后，task7 fused mAP
仅从42.2877变为42.2820，on−off=+0.0058，bootstrap 95%区间
[-0.302,+0.396]。因此，当前动态组最终成绩主要来自联合训练后的
Selector/Prompt/head等共同适配，不能归因于内容路由专家的直接贡献。

本轮不应进入 test、扩 seed、跨任务专家复用或合并 main。下一版应保留
插入位置与图片证据，先让专门专家获得足够样本和可观的前向贡献，并用
系数一致的控制组重新隔离动态路由价值。

## 4. Router 已不坍缩，但专家贡献失衡

未训练探针已确认归一化图片证据相邻样本距离为
Full0.375/Person0.580/Face0.565，远高于 raw task CLS 的
0.0125/0.0173/0.0233。训练后全部任务/视图的最大专门专家占比为
27.3%–57.1%，有效专门专家数为2.55–5.62；多数任务/视图有4–6名
专门专家达到至少1%使用率。task7 的路由计数为：

- Full：`[62,693,145,419,700,378]`，最大占比29.2%，有效数4.85；
- Person：`[248,153,86,397,244,1269]`，最大占比52.9%，有效数4.04；
- Face：`[19,193,905,201,5,1074]`，最大占比44.8%，有效数3.29。

所以继续调高温度、噪声或负载约束不是首要方向。路由多样性已经出现，
但部分Face专家仍只有5/2397或19/2397次调用，而且共享专家接受全部
三视图样本。task7 checkpoint 的实际输出诊断如下，数值均在乘最终
residual scale 0.1之前：

| 视图 | shared/input | specialist/input | combined/input | shared与specialist余弦 |
| --- | ---: | ---: | ---: | ---: |
| Full | 3.510 | 0.304 | 1.848 | 0.393 |
| Person | 3.509 | 0.270 | 1.833 | 0.358 |
| Face | 3.509 | 0.263 | 1.830 | 0.387 |

专门专家的 `up.weight` 并非保持零值；task7 共享专家范数3.351，六名
专门专家约1.80–1.95。问题出在专门专家分流后每名获得的数据和有效
激活不足，而不是 Router 没有更新或专家完全没训练。

## 5. 同权重 MoE-off 消融

只读关闭残差、保留联合训练后其他参数，dynamic 的 on−off mAP 从
task0 的+1.4706逐阶段降到task7的+0.0058；8阶段平均仍为+0.4907。
shared_fixed 从task0 +1.6043降为task7 −0.0670。view_fixed 的直接
残差作用始终为正，task0 +2.0198、task7 +0.5138，但其整体模型仍低
B0 0.2155。

task7 dynamic 的分支 on−off 为：fused +0.0058、Full +0.0260、
Person +0.2026、Face +0.0003、可靠Face −0.1151。Face 相对B0的
+0.6812几乎全部来自联合训练轨迹，而非推理时动态专家残差。
这证明“Router 不坍缩”与“Router 对预测有用”是两个不同条件；v2只满足
前者。

## 6. 下一版解决方案

首选 v3 保持索引1 Task Forward、Drop & Replace 后与 FFN 并联，继续
使用已验证的归一化图片证据，不改 Frozen Forward，也不加入跨任务复用。
只解决专门专家训练不足和控制组系数不一致：

1. 每任务从7专家缩到4专家：1名必经共享专家 + 3名专门专家。三名专门
   专家对应可学习内容路由，不与视图硬绑定。这样每名专门专家获得更多
   样本，每任务参数从707776降至约403456，减少约43%。
2. 专门路由改为训练和推理一致的稀疏 soft Top-2（在3名专门专家上归一
   化），取消 hard argmax 的直通估计和训练噪声。路由仍会随图片变化，
   但两个被选专家都得到与实际推理一致的梯度。
3. 三个控制的共享分量系数必须完全一致。当前 `shared_fixed` 使用
   `1.0*shared`，dynamic/view_fixed 使用`0.5*shared+0.5*specialist`，
   因而不是严格隔离路由的控制。v3 的shared-only固定为`0.5*shared`；
   fixed与dynamic都使用`0.5*shared+0.5*specialist`和相同residual
   scale。固定视图控制也固定选择两名专门专家并使用同样的归一化权重，
   使它与dynamic soft Top-2的活跃容量一致。
4. 在训练日志中新增 shared/specialist/combined 的输出范数、夹角和
   每专家硬/软负载。成功条件不是路由熵，而是专门/共享输出范数比至少
   达0.25、关闭specialist使validation有可重复下降，同时dynamic超过
   系数匹配的shared-only与view-fixed。
5. 先跑task0–2同预算 validation 筛选。只有 specialist 消融确有贡献且
   dynamic 不低于控制，才跑完整8任务seed0；只有最终与阶段平均都超过
   B0/控制并且分支无明显Person退化，才补seed1/2，最后再锁定一次test。

本候选把“小池+soft Top-2”作为一个解决数据碎片化的最小机制包，先用
task0–2低成本筛选。若其专门输出仍明显偏小，第二步才增加独立的 specialist
输出归一化或更高 specialist LR；不要与首个 v3 同时修改，以便确认因果。
若专门输出达到目标但 mAP 仍无收益，应停止该 Task-Forward MoE 路线，
转向只对可靠Face做受限的后置视图校准，而不是继续增加专家或修改 Router。
