# 从既有摘要的重读，转向交互专用Patch Summarization

2026-10-29。按用户要求，仅分析和制定计划；未修改模型、训练、评估或脚本代码，未启动实验。依据0e366d9四组完整八任务结果、原模型数据流及[MULTI-LANE §3.3、式(3)、图2/3](https://arxiv.org/html/2405.15633v1#S3.SS3)。下述并行取证支路是本项目待验证的改造，不是原论文已有模块。

## 一、研究问题应怎样收窄

已有事实：原三路强B0 Test最终/阶段平均32.6800/39.5292；后置CLS-MLP32.7139/39.5923；固定摘要Attention32.6684/39.5668。内容门控接近任务常量，三Attention实际写入均接近1%上限；task6 Sadness/Sensitivity/Suffering是共同薄弱点。原Full/Person/Face、原参数和随机流均受保护。

因此不能再把“加Attention”和“更复杂的门控”当作目标。待检验的问题是：

> 在保留原任务表征学习的条件下，为最终三视图交互单独学习一份摘要，能否得到原任务摘要之外有用的补充证据？如果可以，动态Attention读取是否比同输入的简单池化更有效？

“原摘要丢失有用信息”目前只是一个机制假设，尚未被实验直接证明。先把取证和组合两种职责分开检验，不预先命名姿态/表情/场景专家，不承诺达到双模型均值33.6248。

## 二、MULTI-LANE中的位置和职责

原方法用Frozen Forward的中间图像tokens g和任务Patch Selectors s_t做Summarize，压缩为Summarized Patches G；任务CLS与G进入MSA/Prefix Tuning，随后Drop & Replace和FFN继续更新原任务路径。三视图扩展中，同一任务的原查询分别读取Full/Person/Face，产生不同摘要，再经三路Task Forward得到hF/hP/hR，固定融合为h0。共享查询不等于摘要相同。

当前新增分支接收sg(GF/GP/GR)，只能重新读取已经压缩的证据；新增目标不能教原Summarize改为读取其他线索。候选把这个边界前移：从sg(g)重新做一份对新增查询可导的Summarize，但保持原Summarize和原Task Forward完整。

```
一套冻结ViT权重，分别编码Full / Person / Face
                  ↓ 各层图像tokens
    ┌─────────────┴──────────────────┐
    ↓                                ↓ 第6层只读缓存
原任务Patch Selectors            stop-gradient图像tokens
    ↓                                ↓
原Summarize                     交互专用Patch Selectors
    ↓                                ↓
原三路Task Forward              并行Summarize
MSA / Prefix / D&R / FFN         GF_I / GP_I / GR_I
    ↓                                ↓
hF / hP / hR → 固定融合h0 ──→ 联合Attention或池化MLP
                    │                ↓
                    │            统一限幅delta
                    └──────────────→ h0+delta
                                      ↓
                                同一原分类头
```

图中h0/hF/hP/hR均属于任务t。新增支路不把tokens写回Frozen Forward，不替换原Selectors，不把新增摘要塞回原Task Forward，也不再建一套12层Task Forward。原Image-token Adapter仍按历史配置在index1的图像证据读取路径工作，不画成更新Frozen Forward；第一版新增Summarize仅使用index5的现有归一化图像tokens。

先缓存第6层tokens/原层Selectors，等原三路最终CLS形成后，再产生交互Query并读取新摘要，数据流没有循环依赖。

## 三、首版候选的最小定义

### 1. 两种Selectors职责分开

- 原任务Selectors s_t：由原B0监督更新，用于原三路任务表示。
- 新交互查询：每任务一组10个768维偏移U_t，三视图共用，初始U_t=0；只在新增Summarize中工作。
- 联合Attention的Query q_t(x)：仍由sg(h0_t)、sg(hP_t)产生，用于读取已经提取出的三份新摘要。它与上一步的Patch Selectors不是同一个Query。

为避免新查询仅通过增大模长、改变softmax温度获益，建议首版保持与原层查询相同的模长，只学习方向：

`b_j = sg(s_t,j^(6))`

`qI_j = ||b_j|| × (b_j+U_t,j) / ||b_j+U_t,j||`。

零范数采用明确安全回退；正常原查询非零。U=0时数学上qI=b；不能宣称原AMP缓存与新FP32实现天然逐位相同，后文用共同重算路径控制数值。模长保持是本次拟议的控制规则，不是已验证增益模块，不再同时搜索温度、查询数或新归一化形式。

这10个新查询是任务参数，不是每张图片一个自由参数，也不是三个独立视图各10个新参数。图片变化通过g_v进入摘要；任务私有不等于人物私有。若同一Full图对应多人，任务查询本身并不显式绑定某个人，Person/Face裁剪及后续Person条件Query提供部分对应，但并不保证归属正确，必须做人物交换验证。

### 2. 沿用Summarize运算，改变其监督职责

对视图v：

`GI_(t,v)=softmax(qI_t · sg(g_v)^T / sqrt(D)) · sg(g_v)`。

第一版保持全局Full（包含原规则允许的CLS/patch），不硬截取人物框，不假定三个裁剪相同patch索引对齐。三视图各得到10份768维摘要。

停止梯度的是图像tokens和原查询，GI必须保留对U的梯度；如果再次整体detach GI，新查询将无法学习。新增摘要只送入交互支路。

### 3. 首版交互读出尽量不变

沿用第6层证据、64维/4头/单层Attention、视图类型编码和64→512输出投影。Query仍使用h0/Person CLS，不同时加多Query、多层Attention、专家、位置分支或新分类头。

Face不可靠时在Attention softmax前mask掉Face keys/values；池化组同样令Face聚合结果为零并提供可靠性标记。不可靠Face仍可通过Full/Person产生修正，不能承诺最终融合等于B0；应保证改变无效Face像素不会改变预测。

### 4. 冻结幅度设置，只检验证据和读出

四个首版组统一`delta=B_.01(raw;h0)`，不启用学习门控，输出投影零初始化。它保证最多1%，不保证每人都达到同一范数，也不保证AP提升。

本轮已经暴露“限幅前标量接近被归一化抵消”，所以不在此次取证消融里同时修复或重训门控。保留Null证据也不能自动视为有效拒绝：必须看最终delta，Null权重变化可能被后续限幅抵消。实际RMS分布、饱和比例、logit改动都应报告。

## 四、训练仍是一个自行训练的模型

所有组从同一个标准CLIP视觉预训练和fresh任务参数开始，原B0在同一30轮训练内照常学习；不先安装历史B0参数，不用A/B提供答案，不在末端换头。

原监督L_base继续按照历史融合/辅助BCE及Adapter-ASL分工，更新原Adapter、Selectors、Prompts和当前类别head。新增监督为：

`L_I = BCE_current(H_sg(W)(sg(h0)+delta), y_current)`。

实现时保持历史当前类mask、分母及损失缩放约定，不能顺手改变legacy_full_zero的数值尺度。L_I只更新U_t和新增读出参数，不向原tokens、原Selectors、h0或head回传。

两边使用独立optimizer/scaler/RNG，原路径逐任务参数、关键loss及随机流必须与强B0精确一致。原三视图监督内部的共享参数作用依旧存在；隔离的是新增目标，不能说三路监督从此互不影响。

输出投影零初始化会使第一步的新查询梯度为零，这属于链式求导的正常结果；应在输出投影经过更新后的若干步检查查询梯度和参数变化，避免误判成断路。

不要增加仅为`L_I−L_base_detach`的所谓互补损失：减去对新参数为常数的项不改变梯度。也不先用摘要正交/多样性约束代替最终互补收益；相关摘要也可能有用。

任务结束后封存该任务U及读出参数，后续不更新、不跨任务复用。推理时仍运行所有已见Task Forward及对应交互分支，输出各任务所属类别并拼接；不存在挑选最好任务或Router。

## 五、核心对照应为完整2×2，而不是三个不闭合的组

| 新支路的摘要查询 | 同输入池化MLP | 联合摘要Attention |
|---|---|---|
| 沿用原查询，U固定为0 | 原摘要＋池化MLP | 原摘要＋Attention |
| 新增查询U可学习 | 新摘要＋池化MLP | 新摘要＋Attention |

“沿用原查询”不表示图片摘要固定成常量，也不表示原Selectors停止原训练；它只表示新增目标不能更新查询。四组原B0仍动态学习相同轨迹。

首版四组的新摘要统一从相同LayerNorm后tokens和原查询重算，使用相同FP32 Summarize实现，避免一个组用旧AMP缓存、另一个组用新算子。U=0时验证四组重算摘要相同；原B0继续完全走旧代码。既有DOSE_FIXED可作历史参照，但不能替代改变了摘要数值路径的配对新控制。

共同Query/Value/Output投影和视图编码先构造、按任务/组件独立种子初始化，再构造不同读出算子，避免Key或MLP参数数量改变共同初始化；所有新增初始化仍隔离原CPU/CUDA随机流。

同输入指同一图像token来源、摘要数、预处理、有效性mask和Query条件；可学习组U在各自目标下会分化，训练后摘要不要求逐值相同。比较必须结合四个训练组与条件干预，不能把全部差异唯一归因推理时softmax。

### 近等参数的同摘要池化MLP

建议共享同样的768维摘要归一化/视图编码、768→64 Value投影及1024→64任务/Person Query投影。每视图对10份Value做平均，拼接q、三路64维池化及Face标记（257维），接257→152→64 GELU MLP，再用同样64→512输出投影。

此时固定Attention每任务198912参数，池化MLP约198768，差144（约0.07%）；新查询组两者都再增加7680/任务。Pool组用非线性聚合替代Attention的Key投影及softmax读取，信息来源和预算接近，仍应记录实际FLOPs/显存，不能宣称两个计算完全等价。152为配平参数的计划值，不是调参得出的性能最佳宽度。

保留原B0和已完成的最终CLS-MLP作为强参照；只有原函数精确重放、协议一致时才复用其已核验结果，不能为省成本接受更弱新基线。

四个比较的解释：

- 新摘要Attention超过原摘要Attention：支持新查询在这套读出里有价值，但还不能排除额外参数的一般适配作用。
- 新摘要MLP也获得类似收益：更支持取证改善，不能将主要贡献归给Attention独有机制。
- 新摘要Attention同时超过新摘要MLP：才支持在匹配接口下，动态摘要读取有额外价值；还需入口/内容干预和重复seed。
- 两个新摘要组都无收益：停止此位置“新增查询能提供有效补充”的假设，不继续增大查询数或层数。

可报告差上差`(新摘要Attention−原摘要Attention)−(新摘要MLP−原摘要MLP)`，它是描述性有限差分交互，不是独立且唯一的机制因果证明。若出现正收益后用于论文论证，可再增加“原摘要后同尺寸可学习偏移”的容量控制，区别重新读取图像tokens与一般增加参数；首轮不同时铺开更多组。

## 六、拟议配置与执行顺序

保持seed1，EMOTIC 8task、每任务30epoch、B64、Adam/cosine/WD0；主LR.0125、Adapter/新增读出LR.0004，U首版LR也固定.0004。不搜索U学习率。b32/index1/scale.03、10原Selectors、原Prompts、Adapter-ASL/aux.1/Person颜色扰动关闭、72线程/AMP-TF32/CPU原batch sigmoid均保持。

先做形状/梯度/恢复测试和两任务少量更新smoke，只用于实现检查。正式效果评估直接覆盖完整8任务seed1、Val和Test，不用task0–2的好结果作为晋级证据，因为已知失败集中在task6/7；不从历史task5拼装参数后只训task6来冒充完整轨迹。原RNG严格重放后，B0/CLS-MLP可作为已有锚点，不额外训练第五、六组。

后续若用户授权执行，仅GPU0，按实际显存自动排队；源数据/CLIP/Face manifest沿现有已核验路径。新输出建议`output/private_summarize_attention/<run_id>`、日志`logs/private_summarize_attention/<run_id>`；具体命令和运行commit应在实现并通过预检后声明，此处没有可执行新入口。

机制预检须覆盖：初始delta=0、U=0摘要重放、四组共同投影初始化、U更新非零/原参数梯度不变、无效Face像素阴性控制、原函数/RNG精确、旧任务封存、双优化器完整恢复、输出1%上限、无全mask softmax/NaN。原路径变化属于实现失败，不能带漂移报告精度。

正式保留所有预声明组的完整八阶段结果，不按Test挑epoch、任务、类别或移除分路作为新正式结果；Test已经参与开发，需要如实披露。预算/配置在启动前锁定，不以梯度非零或摘要变得不同替代效用判断。

## 七、必要归因：确认新摘要提供的是有用内容

优先task0/2/6/7，特别保留task6；固定完整评估人群和当前任务类别mask。

| 归因 | 保持什么不变 | 能回答什么 |
|---|---|---|
| 关闭整个delta | 同checkpoint的原三路和head | 新分支的条件净贡献；应精确回B0 |
| 仅将U恢复0 | 同checkpoint读出与原路径 | 训练好的新查询是否被读出依赖；不是重训原摘要控制 |
| 移除新增Face/Person memory | 原h0、交互Query、head均保持 | 单独入口的贡献；禁止再同步改Person Query |
| 只交换Person条件Query | 自己的h0和全部memory不变 | 内容Query是否提供了人物相关条件 |
| 同图多人交换新增Face/Person证据 | 接收者h0/Query/有效mask及原Face路径保留 | 是否优先利用当前人物证据；报告样本量及同图相关性 |
| 固定TRAIN均值方向/错配修正方向 | 接收者实际delta范数、原h0/head不变 | 是否真正需要图片对应的修正方向，而不只是通用方向 |

常量方向从事先固定TRAIN图片标定，不用Val/Test选向量。错配在可靠性等质量标记相同的组内进行，使用固定私有RNG；仅为诊断，不能作为部署时使用其他Test图片的方案。保持每人原delta范数才能避免方向错配又混入幅度变化。

人物交换优于非交换的差别只能支持相应人群的条件证据依赖，不能自动证明严格人物绑定；Full tokens经过全局注意力，任务私有查询仍非显式人物位置约束。仅看Attention热图、Face质量标记或多样性不够。

记录各任务/epoch的U梯度/模长/方向变化、摘要方差与相似度、Attention分配以及最终RMS分位数/近上限比例；对Sadness/Sensitivity/Suffering记录逐类AP、BCE和正负样本排序翻转，检查新摘要是否真正缓解共同薄弱点。不同摘要、较高Face注意力或更低TRAIN BCE都不是成功本身。

## 八、成功判据和停止条件

第一层：原B0函数和历史训练精确保持，否则不进入效果比较。

第二层：新摘要Attention在Test最终/阶段平均都优于原摘要Attention，说明该接口改动有候选价值；同时完整报告Val，不能以Val替代Test目标。

第三层：要宣称Attention有独特价值，还必须在两项Test上优于同输入的新摘要池化MLP，并超过原B0与最终CLS-MLP参照。只有新摘要MLP改善时，论文贡献应围绕可学习摘要提取，而不是强行归功于Attention。

第四层：期望Face入口在最终和阶段平均有正条件贡献，至少不能重现task6的系统损害；主结论不依赖关掉某一路或去掉某类。按原图聚类给出配对区间，若完整结果有足够实际收益，再预声明seed0/2的配对复核；不从多次运行挑最好seed。

若相对强控制仍只在当前0.03–0.07点小波动附近、条件区间跨0且互补归因不支持，不扩大查询/Attention/门控。不同时加入排名loss、共享参数放开、输出尺度搜索或区域mask。新查询与归属是不同问题：如果交换实验表明Full对应仍不可靠，下一阶段应另立“人物条件取证”对照，不能将现有任务私有U称为已经解决人物绑定。
