# 从双模型互补到单一三视图模型：下一阶段研究方案

2026-10-27执行修订：用户明确要求学生自己训练成型，故下文“A初始化＋B0头复制”不作为本轮执行方案。新方案见[self_trained_view_transfer_execution_20261027.md](self_trained_view_transfer_execution_20261027.md)：CLIP预训练之外任务参数/head全新初始化，自己的30epoch硬监督＋5epoch约束，教师只提供目标，最终推理不组装外部参数。以下作为历史设计记录保留。


2026-10-27。用户已授权先验证固定均值，再研究如何用预先定义的流程得到一个推理模型。本文件是后续训练候选，尚未修改训练器或启动训练；R5真实前向的执行配置另见fixed_model_mean_execution_20261027.md。是否保留本候选须依据完整R5结果。

## 1. 研究对象：保留预测功能，而不是搬运参数块

A是Person-only Attention共训的完整三视图模型，B是Person+可靠Face Attention共训的完整三视图模型，二者使用同阶段B0头。它们的功能来自Image-token Adapter、Task Selectors、Prefix Prompts、摘要Attention与Task Forward的共同适配。新实验不再将一个孤立的Attention或Selector搬入另一模型，再期待保留原功能。

固定均值若成立，说明两套完整预测存在互补；它尚不能区分Face监督改变的学习过程、普通模型集成、标度差异或误差抵消各占多少。尤其不能把较弱的B单模型或B Full单路直接丢弃，也不能说“Face提升必然损害Full”。

下一阶段的核心问题应改成：**在相同三视图信息和共同读出空间内，一套任务参数能否学到双来源共同输出的有用修正？** 它仍是MULTI-LANE三视图模型，而不是把多视图信息强行压到仅输入Full的模型。

## 2. 先保留最必要的强对照

R5真实模型必须重放A/B来源，并与当批logits均值对照；否则训练目标的上限尚未确认。后续论文实验还必须比较同预算两个Person-only模型的固定均值，才能判断A/B差异是否有超出普通集成的价值。该控制需要独立训练第二个A，不能用同一个checkpoint复制两次冒充独立模型，也不能直接用另一个seed的最好结果挑选组合。

完整来源包括B0头训练、A训练和B训练各30epoch/任务，必须一起报告。下面的学生适配还会增加预算，不以推理只有一个模型掩盖训练成本。现有checkpoint可用于初步可行性验证，最终方法应事先定义每任务的来源训练与迁移流程，不在看过Test后自由挑选部件。

## 3. 推荐的首个单模型候选：同输入的融合功能迁移

教师保留A/B整条来源函数，均冻结；学生保留一套A拓扑的三视图MULTI-LANE。学生仍有Full、Person、Face的Task Forward，仍共享当前任务的一套Adapter/Selectors/Prompts，仍保留A原有Person Attention。本轮不再新增Face Attention、MoE或视图私有Selector，以免同时改变容量。

```text
同一组增强后的Full、Person、Face及同一个Face mask
         ├→ 冻结A三视图 → Summarize → Task Forward → 融合 → B0头 ─┐
         ├→ 冻结B三视图 → Summarize → Task Forward → 融合 → B0头 ─┤
         │                                        固定各取一半 │
         │                                            stop-grad
         └→ 单一学生三视图 → Summarize → Task Forward → 融合 → 同阶段B0头
                                                           ↑
                                               原硬标签目标 + 功能匹配

最终部署仅保留学生；A/B不参与推理。
```

“同输入”要求教师读取学生这次实际消费的增强图片tensor，而不是缓存另一种裁剪下的固定概率。教师eval/no-grad，学生按预定训练模式；可靠Face掩码严格一致。教师没有看到validation/test标签；但它们已在同一TRAIN上训练过，因此不能把这些TRAIN输出声称为OOF或教师未见数据。

### 3.1 为什么先匹配共同分类头后的功能

R5目标为`zT=.5*zA+.5*zB`；学生输出为`zS=H_B0(hS)`。首版只匹配当前任务类别的融合logits，不同时规定“Full必须等于A、Person必须等于B、Face必须等于另一来源”。后者会再次给一套共享参数施加可能不相容的分路目标。

也不直接逐槽匹配不同来源的Summarized Patches：Selector槽位未证明有相同语义。逐视图单位特征的均值通常不再是单位向量，强迫学生L2归一化后的单路特征精确等于该均值也可能不可实现。共同B0线性头提供可比的读出空间，匹配最终功能比强迫内部坐标逐元素相等更直接。

候选功能项为当前类别logits均方差`D=mean((zS-stopgrad(zT))^2)`，保留绝对logit偏移而非按样本中心化。多标签问题不用互斥类别softmax。首版不增加温度、排序pair、置信度掩码或人群门控；这些会把一个问题同时变成多项搜索。

### 3.2 不破坏ASL分工

沿用原融合监督和0.1视图辅助监督，硬标签权重保持1.0。Face辅助监督仍只用可靠人群。参数组目标分别定义为：

- Selectors/Prompts/现有Person Attention：`L_BCE原 + beta_M*D`。
- Image-token Adapter：`L_ASL原 + beta_A*D`；ASL保留gamma_neg9.8、gamma_pos0、clip.05。
- 共同分类头在此额外阶段冻结；它先前已由对应阶段B0学习当前类别，不是永久冻结未来随机类别头。

有意识地比较是否将功能项传给Adapter，不能把D偷偷并入BCE后误以为Adapter也受到了保护。现有runner用显式autograd分配BCE/ASL梯度，新增约束需要在两个目标上分别定义和审计。

beta尚未锁定。若进入实现，建议在固定TRAIN校准batch上按原监督梯度范数确定一次，使初始D梯度约为对应原梯度的0.25倍；只用TRAIN，随后全阶段固定，不按Test逐次调。梯度范数只用于定标，不证明梯度冲突或给出泛化保证。若某组D梯度为零，则记录并按预先规定回退，不除以接近零的量。不能只报告“lambda=1”而忽略D与ASL量纲差异。

### 3.3 每任务边界的增量保护

对任务t，来源使用对应task t checkpoint，不使用task7教师提前指导task0。学生当前任务槽位由A的同任务已学习参数初始化；已完成的学生任务槽位保留，不能每次重载整份A而抹掉学生进度。共同头仅初始化当前任务的新类别行，旧类别行保留已封存学生读出；冻结参数和旧类别行须逐值审计。

本轮迁移只使用当前任务合法训练人群/类别，旧任务Adapter/Selectors/Prompts/Attention及其读出冻结。旧预测是否保持要用固定TRAIN探针核验，不因Frozen Forward冻结就宣称Full或旧任务功能自动保持。不能通过validation/test回流训练或选样本。

学生适配不覆盖下一任务A/B的原始训练随机流和起点。若以后改成学生传递到下一任务教师训练，属于另一条训练轨迹，必须单独控制和报告。

## 4. 最小训练矩阵与建议预算

以下均是候选，不是已启动实验：seed1，batch64，workers2，72线程，AMP/TF32，旧seen-positive标准；以每任务额外5epoch、Adam每任务重置、cosine、LR.0004、WD0为初始预算。所有组相同初始化、batch顺序、增强tensor和成功更新数，不按组改变epoch。

| 组 | 保留什么 | 额外训练目标 | 回答的问题 |
|---|---|---|---|
| U0 | 原A+B0头 | 不训练 | 32.8864/39.8687参照与来源重放 |
| U1 | A学生，同阶段B0头冻结 | 原BCE/ASL，D=0 | 额外训练本身会造成什么变化 |
| U2 | 同U1 | D只进入主参数，Adapter仍仅原ASL | 在保留Adapter目标时能否迁移融合功能 |
| U3 | 同U1 | D同时进入主参数与Adapter | 是否需要Adapter共同适配，能否避免旧适配损失 |

如果U2/U3有效，再单独比较分类头允许小步更新；不在首轮同时换头、加Face模块、改路由和增加epoch。U1不能用之前“从B0额外5epoch”结果代替，因为本次起点是已共同训练得到的A，功能目标和参数关系不同。

首轮训练可先task0/2/7代表性当前任务槽位诊断以排除实现错误；不能将非连续训练的这些点称为完整增量结果。正式结论仍须完整8任务Val/Test的最终和阶段平均。Test已参与探索，报告所有预声明组，不只挑最好最终mAP。

## 5. 判断成败时看什么

1. 首先检查U2/U3是否同时优于U1和U0的Test最终/阶段平均；仅拟合D下降或Face单路更强不算成功。
2. 同报每阶段、每视图、可靠/不可靠Face、同图单人/多人、类别AP和cF1/oF1。不能用子群mAP按人数平均来替代总体AP；跨人群排序也是目标的一部分。
3. 统计学生与教师在TRAIN及eval上的logit距离、排序一致性、正负类分布；区分“训练集拟合不下”“训练集可拟合但泛化失败”“head/表征发生不良变化”。这些统计用于解释，不从Test生成下一轮训练掩码。
4. 测量学生最终参数、显存和时延是否回到单来源水平；训练教师成本单列。蒸馏成功也只是单模型功能迁移证据，还需要同预算普通集成、其他seed与组件控制才能作为新机制的论文论据。

## 6. 既有失败路线约束了本候选的范围

9月已失败Person/Face OOF→Full概率蒸馏、强R1→Full概率蒸馏和OOF纠错排序；最后一项Val最终/平均下降2.6785/3.2720，不能重新包装为本轮新方法。本候选与它们的实质区别是学生仍看三视图、教师/学生每次读取同一增强tensor、目标是已验证完整模型均值的最终功能、硬标签不被混合稀释、ASL/BCE路由明确。

这只是更合理的接口，不构成成功保证。强教师也可能无法被当前共享任务参数库吸收；保留原硬标签不保证兼容；固定头也不保证表征不会变坏。若U2/U3仅降低TRAIN的D却无法胜过U0/U1，应停止继续调beta、温度或epoch。优先承认当前增益依赖双来源互补，或另行研究有明确证据的容量/训练冲突，而不是预先宣布Face梯度是唯一根因。
