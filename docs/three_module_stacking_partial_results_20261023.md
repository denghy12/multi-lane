## 从MULTI-LANE数据流看，三个模块为什么不天然互补

原结构中，Frozen Forward提供图像tokens；任务Patch Selectors通过Summarize读取各视图的Summarized Patches；各视图保留自己的Task Forward，最后融合任务特征。当前三个模块都作用于这条证据读取链，而不是三个相互独立的信息源。

```text
三视图Frozen Forward原始图像流保持不变
  │
  ├─第2层：A分别改写三视图用于Summarize的图像K/V
  │         → 改变当前任务lane的读取与后续状态
  │         （不写回Frozen Forward，不将改写patch直接送到第6层）
  │
  ├─各层Full Summarize：C将目标框几何偏置加入选择softmax
  │         → 改变Full的Summarized Patches
  │
  └─第6层：B以任务Patch Selectors为Q，Full摘要为K/V
            → 残差写入Person摘要
            → 原Person任务MSA、Drop & Replace、FFN

Full/Person/Face三条Task Forward → 原固定特征融合 → 原分类头
```

**A与B可能相互补偿，但当前证据不能确定这种补偿发生在推理还是共同训练。**A改变早层Selector读取的特征度量及Value，B改变中层Person任务路径接收的Full信息，两者有不同作用位置，可能共同改善任务表示。另一方面，A/B单独最终均略低于基线，组合变好也可能是共同优化Selector、Prompt和head产生的补偿，并不意味着已经识别出两个独立有效的融合模块。尚需运行中的残差关闭对照区分。

**A与C会共同改变Full摘要的生成条件。**A改变第2层图像K/V和任务状态，C直接改变Full选择权重；它们共享任务训练目标，并非“特征增强＋一个无关的位置提示”。一种机制假设是：几何偏好限制了适配后的Selector读取，或改变了任务状态的优化方向，使部分全局情境证据被削弱。但目前C的注意力改变量很小，且未完成关闭归因，这只能作为待验证解释，不能断言其已经抹掉关键背景。

**B与C也没有自动解决目标人物对应。**B使用的是任务Selector Query，C提供的是目标框几何；二者都不等价于用当前人物的外观内容核验“Full里的证据属于谁”。被位置改变的Full摘要会被B继续写入Person，同时Full自身仍在末端占较大融合权重，因此可能重复同一证据、减少独立性，也可能带来补充。这种风险由接口决定，但本轮还没有证实具体哪一种发生。

按最终mAP计算的二阶交互：A×B为+0.6545，A×C为−0.6438，B×C为−0.0236，三阶交互仅+0.0028；对应区间全部跨0。点估计更接近“A/B补偿与A/C负交互大体抵消”，不是额外出现巨大三阶崩溃。不能把三模块回落简单讲成模块越多越容易坏；C仅60参数/任务，三模块相对A+B总共只多480参数，单纯参数量也不是充分解释。

## 模块是否真的工作：日志排除了什么，仍没有证明什么

摘要Attention并非始终输出接近零。按各任务30epoch累计训练统计，B单独的残差/Person摘要范数比约0.069–0.536；A+B约0.047–0.637；三模块约0.053–0.561。task7的B单独/A+B/三模块分别约0.235/0.233/0.174。输出已经能显著影响Person，不能默认归因为“Attention没学起来”，但范数大也不证明写入方向有利。

Adapter具有明显任务差异。以三模块最后一个epoch统计，task3的Full/Person/Face残差比约0.058/0.128/0.195，而task6仅约0.000066/0.000078/0.000077；不同任务不能用一个全局scale解释。task6残差很小可能意味着适配未充分形成、被共同优化抑制或无需这种残差，现有数据无法在这些解释间选择，也不能据此直接提高LR。

位置模块梯度非零、参数有变化，未出现tanh饱和。各任务训练统计的注意力KL约3e-6至1.24e-4，直接改变读取权重的幅度较小。因而“位置bias过强或饱和压住其他模块”目前缺乏支持；更需要辨别微小训练扰动、任务特定优化变化与实际推理证据选择。

以上都是训练期间统计，不能代替同checkpoint在validation的残差开关。三视图分支收益、Face可靠性分层和最终test尚未齐全，也不能现在宣称Person或Face互补性已改善。
