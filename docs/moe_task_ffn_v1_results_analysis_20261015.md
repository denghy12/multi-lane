# Task-Forward MoE 首版：完整结果分析与下一步

## 可比口径和训练完整性

正式批次 `moe_task_ffn_v1_seed0_20261015_01` 的训练代码为
`17a9b84`，8 tasks × 30 epochs，13950 次成功 optimizer update，
0 次跳步；冻结 CLIP SHA 不变，峰值 reserved 3022 MiB。训练使用
EMOTIC 三视图、seed 0、batch 64、Adam/余弦调度、任务顺序
`5/3/3/3/3/3/3/3`。与静态 MoE v2 报告的 B0 对照相比，
初始 Selector/Prompt/head SHA、CLIP SHA、8任务训练样本 SHA、
每任务第一批样本 ID、采样规则和主要训练超参数一致。

原 `val/`、`test/` 按“已见类别至少一个正例”筛选人群，前7阶段
不可直接与 B0 的固定全人群曲线比较。后续用原 8 个 checkpoint
只读重评估，`full_val/` 每阶段固定2397人、`full_test/` 每阶段
固定5368人；两路 exit 0。最终 task7 的样本 ID、标签、类别顺序
与 B0 逐项一致。比较阶段曲线只使用 `full_val/full_test`。

## Router 实际学到什么

所有 8 个任务、三个视图，在完整评估人群上，每个任务/视图的
确定性 Top-2 都是固定同一对专家。每任务22个专家里，三视图
合计只调用5–6个；6/8任务的三视图专家对完全不重叠，另外
2/8任务只重叠一个专家。因而“一个共享池”并未转化成
三视图实际共享专家。全部22个专家的 up 权重范数都非零，
说明其余专家训练时曾更新，但评估时没有被选用。

task7 checkpoint 在 validation 前64人上的 FP32 Router 探针：
Full/Person/Face 的 CLS 样本间 RMS 仅0.0081/0.0083/0.0144，
而共同均值 RMS 为0.2636/0.2650/0.2697。各视图 Top-2 组合
均只有1种；Top-1 平均权重为0.99765/0.99947/0.99910，
标准差小于0.00005，实际上接近单专家。第一与第二名 logit
间隔约6.05/7.54/7.01；第二与第三名间隔仅0.023/0.205/
0.051，而训练噪声预测标准差中位数约0.483/0.362/0.343。
这些数字支持两个机制假设：路由输入由任务共同成分主导，
有效图像变化弱；训练噪声可能改变第二名的派发，但推理权重
几乎全给固定第一名。此处是机制推断，尚非独立因果实验。

## 同权重 MoE-off 验证集消融

`d97f57d` 增加 `--disable-moe-runtime`；对原8个 checkpoint
只读重放同一2397人验证集，除关闭 MoE 残差外不变。exit 0，
结果另存 `full_val_moe_off/`。阶段平均 on47.9082、off47.9747；
最终 on42.0342、off42.5185，off−on +0.4843。
最终分支 off−on：Full +0.8786、Person +2.1521、Face −0.3187。
按原图像聚类配对 bootstrap，最终 fused +0.4843 的95%区间
[+0.0948,+0.9536]，Full 为[+0.5422,+1.2170]，Person 为
[+1.4751,+2.8277]，Face 为[−1.2580,+0.1836]。

同权重消融说明**当前残差在最终 validation 的 Full/Person
分支上有害，并拖累 fused**；但 task1–3 的 off 分数比 on
分别低0.2881/0.2583/0.2172，不能说 MoE 在所有阶段都无用。
MoE-off 权重仍由 MoE-on 训练产生，绝不是重新训练的 B0；
本次没有用 test 做 MoE-off 选择。

## 建议的下一版次序

1. 保留用户指定的 Task Forward MSA/Drop & Replace 后、FFN
   并联位置和 Frozen Forward 不变。先把 Router 输入从共同成分
   占优的 raw task CLS 改为该块已提取的图片证据摘要，并做
   归一化；先量化输入跨图片变化和门控分数，再训练。
2. 把每任务22专家缩成小池，明确设置一个总被三视图调用的
   共享专家，再由每视图内容 Router 选择一个专门专家。
   从4–8个专家、bottleneck64开始，旧任务整池继续冻结；
   这样在结构上保证参数共享，同时仍允许按图片/视图选路。
3. 处理训练/推理门控失配：逐步退火 noisy gating，限制过度
   饱和的门控权重，并尝试很弱的负载约束。记录每个视图
   top1/top2 权重、跨图片专家组合、共享专家使用率；
   不能把“路由不同”本身当成成功。
4. 同位置训练一个固定共享专家控制组、一个固定视图路由
   控制组，再与动态路由同 seed、数据、训练更新数比较。
   先用固定全人群 validation 的最终及阶段平均 mAP、
   Full/Person/可靠 Face 分支和旧类遗忘筛选，test 只作最终报告。
   若仍不能超过 B0/控制组，再重新考虑 Selector 图像证据
   路径，而不是现在研究跨任务旧专家复用。
