# Full、Body、Face三视图共享融合实验总结

> 用途：与导师讨论当前研究进展。本文尽量不使用代码中的实验编号，只说明每个实验为什么做、具体改了什么、
> 得到了什么结果，以及它帮助我们排除了什么。

## 一、我们想解决什么问题

当前任务使用三个视觉视图识别人物情绪：

- **Full**：完整场景，包含人物、动作和环境；
- **Body**：目标人物身体区域；
- **Face**：目标人物脸部区域。

目前效果最好的方法，是分别训练三个完全独立的专家，再用固定权重融合三路预测：

- seed0 validation final mAP：**43.5812**；
- 三个种子的正式test：**33.0119 ± 0.3038**。

但是三个完全独立的模型参数量大，而且固定权重融合较为生硬。我们的目标是训练一个大部分参数共享的模型，
最终再实现按样本、按情绪证据动态选择Full、Body和Face。

目前共享模型的seed0 validation final mAP为**43.0754**，比独立专家固定融合低**0.5058**。因此在设计
动态路由之前，必须先弄清楚共享模型为什么下降；否则Router只能在质量不够好的三路预测之间重新分配权重。

## 二、到目前为止做过的关键实验

### 1. 检查是否存在类似DGL论文中的梯度干扰

#### 为什么做

DGL论文指出，多模态联合训练时，融合损失可能使某些模态得到不合适或不足的梯度。我们想知道Full、Body、
Face共享参数时，是否也存在某一路被融合训练压制的问题。

#### 怎么做

我们比较了三种训练方式：

1. 正常让融合损失和单路辅助损失一起更新共享参数；
2. 切断融合损失回到三路表示的梯度，只保留较弱的单路辅助监督；
3. 使用更完整的DGL式隔离：融合目标主要训练融合决策，单路目标训练视图表示。

同时记录融合损失和单路损失在Full、Body、Face路径上的梯度大小与方向。

#### 结果

| 训练方式 | final mAP | average mAP |
| --- | ---: | ---: |
| 普通联合训练 | **43.0754** | **49.9807** |
| 只切断融合梯度 | 41.4177 | 48.1986 |
| DGL式双向隔离 | 42.4147 | 49.3864 |

DGL式训练比普通联合训练低**0.6607**。在普通训练的八个增量任务中，融合梯度与各单路梯度的平均方向相似度
均为正，没有观察到持续的方向性对抗。DGL式训练虽然改善了部分Body、Face指标和遗忘，但削弱了最重要的
Full分支，最终收益不足。

#### 说明什么

当前结果不支持“持续的破坏性梯度冲突是主要原因”。已经测试的直接梯度隔离方法不能解决问题。不过DGL还
涉及梯度幅度、学习速度等更广泛问题，因此不能据此否定所有DGL思想，只能说当前实现不合适。

### 2. 给三路增加少量各自专用的Adapter参数

#### 为什么做

如果三路完全共用同一种特征适配方式，Full、Body、Face可能难以形成各自专长。因此我们尝试在共享Adapter
之外，为每个视图增加少量专用参数。

#### 怎么做

比较三种结构：

- 一个共享的中等大小Adapter；
- 一个参数更多的共享Adapter，用来判断收益是否只是来自参数量增加；
- 保留原共享Adapter，再为Full、Body、Face各增加一个很小的专用Adapter。

三种方法继续使用相同的固定融合、训练目标和数据，不引入动态Router。

#### 结果

| Adapter结构 | final mAP | average mAP |
| --- | ---: | ---: |
| 原共享Adapter | **43.0754** | 49.9807 |
| 更大的共享Adapter | 42.7028 | **50.1309** |
| 共享Adapter＋三路小型专用Adapter | 42.7961 | 49.7551 |

增加小型专用Adapter后，final mAP比原共享模型低**0.2793**，Full、Body、Face单路指标也都下降。

#### 说明什么

单纯增加参数量没有解决问题；给每路添加很小的专用残差，也没有自然形成更好的三个专家。但这个实验只测试了
“共享主体＋很小的三路增量”，不能代表“Full使用一个完整的私有Adapter”也会失败。

### 3. 检查性能差距是不是由融合公式造成的

#### 为什么做

独立专家是在sigmoid之后融合三路概率；共享模型原本等价于先融合logit再做sigmoid。两者公式不同，因此需要
先排除“只是融合计算方法不同”这个混杂因素。

#### 怎么做

保持模型预测完全不变，只在离线评估时分别计算：

- logit融合；
- 概率融合。

对独立专家和共享模型都做同样比较。

#### 结果

| 模型来源 | logit融合 | 概率融合 |
| --- | ---: | ---: |
| 三个独立专家 | 43.4454 | **43.5812** |
| 一个共享模型 | **43.0754** | 42.8238 |

共享模型改成概率融合后反而下降**0.2516**。

#### 说明什么

共享模型相对独立专家的下降，不是因为错误选择了logit融合或概率融合。固定融合公式不是当前主要问题。

### 4. 像搭积木一样替换三路预测，寻找主要损失来源

#### 为什么做

共享模型的Body和Face单路mAP其实高于独立专家，但融合结果仍然较差。我们需要判断究竟是哪一路预测让整体
融合受损。

#### 怎么做

对Full、Body、Face分别选择“独立专家预测”或“共享模型预测”，组成全部八种组合。所有组合使用相同的固定
概率融合权重，不重新训练模型。

其中最关键的一组比较是：

- 三路全部使用共享模型预测：**42.8238**；
- 只把Full换成独立专家，Body和Face仍用共享模型：**43.7217**。

只替换Full就提升了**0.8979**。在其余三种Body/Face组合背景下，换入独立Full也始终带来提升，范围为
**0.6770～0.8979**。

进一步把独立与共享端点之间的差距分摊到三路后：

- Full是主要负面来源，约解释`+0.7884`的差距；
- Body影响较小，而且与Full存在明显交互；
- 共享Face反而比独立Face更有利，约贡献`-0.1220`的反向差距。

单路结果也支持这一判断：

| 视图 | 独立专家单路mAP | 共享模型单路mAP | 共享减独立 |
| --- | ---: | ---: | ---: |
| Full | **42.3799** | 41.6817 | **-0.6982** |
| Body | 38.3044 | **39.7203** | +1.4158 |
| Face | 33.3521 | **34.7389** | +1.3868 |

#### 说明什么

这是目前最关键的定位实验。问题并不是Face拖后腿，也不是三路都学得更差；主要损失来自共享模型生成的Full
预测，以及Full与Body之间的配合。Body、Face单路mAP更高，却没有自动转化成更高的融合mAP，说明单路排序
性能和“能否纠正Full错误”不是同一件事。

### 5. 检查Full是否需要自己的分类头

#### 为什么做

既然主要差异来自Full，一种最简单的解释是：Full包含场景和人物整体信息，它可能需要与Body、Face不同的
分类边界，而共享分类头限制了它。

#### 怎么做

比较两组同批训练：

- 三路使用同一个分类头；
- 只为Full复制并训练一个独立分类头，Body和Face继续共享原分类头。

除分类头外，冻结CLIP、Selector、Prompt、Adapter、数据、损失和融合权重全部保持一致。

#### 结果

| 指标 | 三路共享分类头 | Full独立分类头 | 变化 |
| --- | ---: | ---: | ---: |
| 融合final mAP | **42.6627** | 41.1145 | **-1.5482** |
| average mAP | **50.3853** | 48.3977 | -1.9876 |
| Full单路mAP | **41.0116** | 39.6184 | -1.3932 |
| Body单路mAP | **40.0137** | 37.4710 | -2.5427 |
| Face单路mAP | **35.4149** | 33.8664 | -1.5485 |

Full独立分类头与共享头最终已经明显不同，因此不是“私有头没有学开”。它不仅没有改善Full，还通过共享的
上游模块改变训练梯度，使Body和Face一起下降。

#### 说明什么

简单的分类头共享不是主要瓶颈，直接拆开Full分类头不是正确方向。这个实验不再补其他随机种子。

需要注意：本次共享头基线把原模型前向等价改写为“每路先过head再融合”，在AMP长期训练下产生了约0.41的
基线漂移。因此本实验可靠回答的是同批“共享头与Full独立头”的比较，不能把新结果与历史共享基线作精确
因果比较。后续实验必须保留历史模型原本的前向计算顺序。

## 三、目前可以得出的结论

目前证据共同指向：

> **共享模型的主要损失表现为Full分支预测质量下降，以及Full与Body的互补关系变弱。问题不在Face，
> 不在概率或logit融合公式，也不能通过简单拆分Full分类头解决。**

固定融合并非完全无效。共享模型中，融合结果仍比Full单路高约1.39 mAP，说明三路确实存在互补信息。真正的
问题是共享训练没有产生质量足够高、配合足够好的三路专家，特别是Full。

因为CLIP主干是冻结的，下一步真正需要检查的是分类头之前的共享可训练模块：

- Image-token Adapter；
- Selector；
- Prompt；
- 以及这些模块所接收的融合损失和单路辅助监督比例。

## 四、目前还不能下的结论

- 还不能直接宣称“三路共享参数导致特征过度相似”已经被证明；目前只有预测接近度等间接现象。
- 还没有确定问题具体来自Adapter、Selector还是Prompt。
- 当前关键比较主要是seed0 validation，用于定位机制是合理的，但不能直接作为论文中的稳定统计结论。
- 独立专家与共享模型的原始`0.5058`差距，在固定模型的原图组重采样中区间跨过0；明确机制后仍需补
  seed1/2训练，验证结论是否跨随机种子成立。
- 当前失败的是具体的DGL隔离、小型专用Adapter和Full独立分类头，不能扩大为“所有梯度解耦、所有私有参数
  或所有动态融合都无效”。

## 五、建议的下一步

下一步建议只做一个最小受控实验：

> **严格保留历史共享模型的原始前向和融合方式，只让Full使用一个完整的私有Image-token Adapter；
> Body和Face继续共享原Adapter。**

Selector、Prompt、分类头、损失、数据顺序、Face可靠性规则和融合权重全部不变。第一阶段只做seed0，并同时
观察：

1. Full单路是否恢复；
2. 融合mAP是否提高；
3. Body和Face是否仍被连带损伤；
4. Full与Body的纠错互补性是否恢复。

如果Full单路和融合同时提高，再补参数量相近的“更大共享Adapter”对照，判断收益来自视图专用性还是单纯增加
容量，并用seed1/2确认稳定性。如果仍然失败，再检查Full专用Selector/Prompt。

只有先得到质量和互补性更好的三路表示，动态Router才有研究价值。否则Router只是重新加权现有误差，难以形成
有说服力的论文贡献。
